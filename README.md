## v0.2 改了什么（权限引导 · 2026-09-23）

真机实测来的需求：安卓 15 起，**直装（侧载）**的 App 会被系统限制敏感权限（悬浮窗、无障碍、
使用情况访问等），开关点了会自己弹回去，用户根本猜不到自己被限制了。v0.2 把这件事讲清楚：

| 改动 | 说明 |
|---|---|
| 首页「① 权限体检」| 悬浮窗 / 通知 / 截屏 / 电池白名单 四项**实时状态**；`onResume` 必刷一次，从系统设置页回来立刻变 |
| 「被系统限制」判定 | **不读系统私有标志位**（换机型就失效），只用三个事实推断：用户点过「检查悬浮窗权限」+ 回来 `canDrawOverlays()` 仍为 false + 用户点了「我打不开这个开关」 |
| `LimitGuideActivity`（新）| 全屏引导页：① 为什么（安卓 15 侧载限制）② 怎么做（**一步直达「应用信息」页** + 各机型入口小抄）③ 然后回来（重新检查）；底部隐私说明；亮/暗两套主题 |
| 首页常驻入口 | 「**用不了？点这里**」蓝色横幅，随时能进引导页 |
| 首启提醒 | `Prefs` 记 bool，第一次启动自动进一次引导页（只自动进一次，之后靠常驻入口） |
| 版本号 | `versionCode 1 → 2`、`versionName 0.1 → 0.2` |

约束守住了：不引依赖、不动包名、不碰识图/翻译链路（`DeepSeekClient` / `TranslateFlow` / 卡片一字未改）。

离线/沙箱环境（读不到 C 盘的 SDK 与 gradle 用户目录）下的完整构建命令见 `引导页-交付说明.md`。

## 必踩的坑（都在真机上踩过了，改代码时别踩回去）

1. **Android 14 起，一个 `MediaProjection` 只能 `createVirtualDisplay` 一次。**
   每次截图新建虚拟屏的写法在 13 及以前没事，14 上第二次必抛
   `Don't re-use the resultData ... Don't take multiple captures by invoking
   MediaProjection#createVirtualDisplay multiple times on the same instance.`
   → 做法：**虚拟屏建一次常驻复用**；屏幕尺寸变了走 `resize()` + `setSurface()`（这俩不受限）。
2. **Android 14 起，截屏授权是"每次会话一次"的**，不是装一次就永久。
   App 进程重启后第一次框选会弹系统授权框（vivo 上是「立即开始」）；
   授权后我们**自动续上刚才那一次框选**，不用用户重划。一个使用时段内只需点一次。
3. **overlay 窗口的坐标原点不在屏幕左上角。** 实测这台 vivo 上 `parent frame = [0,126]`
   （状态栏下方），设 `lp.y=933` 实际落在屏幕 y=1059 —— 直接拿视图坐标裁图会整体偏一条状态栏。
   → 窗口加 `FLAG_LAYOUT_IN_SCREEN`，并且用 `getLocationOnScreen` 动态换算（别写死数值）。
4. **取帧不要"先清空队列再等新帧"。** 屏幕静止时合成器根本不推新帧，清空后就是干等 → 高频超时。
   → 正确做法：不丢弃，按 `Image.timestamp` 挑「隐藏悬浮窗之后」的帧；
   挑不到就用最新一帧兜底（宁可图里多半个球，也别让用户失败）。
5. **自己家的悬浮窗会被截进去**（球 + 译文卡片都是 overlay，也算屏幕内容）。
   → 截图前把球设 `INVISIBLE`、卡片 dismiss，截完再恢复；loading 卡片等截完再显示。
6. **透明页必须 `taskAffinity=""`。** 用 `NEW_TASK` 从服务拉起透明页时，如果它挂在 App 自己的
   任务栈里，`finish()` 之后系统会把 MainActivity 顶到前台 —— 把用户正要翻译的界面盖掉，
   于是截到的是自家 App。
7. **Android 10+ 后台读写剪贴板都会被系统拦**（读返空、写静默丢弃，都不报错）。
   → 读和写都要走透明 Activity，而且**必须等 `onWindowFocusChanged` 拿到焦点之后再动手**；
   在 `onCreate` 里读，窗口还没焦点，照样读不到。
8. **同类 overlay 后加的在上层**：译文卡片后加会盖住悬浮球，球就点不动了。
   → 卡片出现后调 `FloatingBallService.bringToFront()` 把球抬回最上面。
9. **全屏 overlay 抢返回键**：`FLAG_NOT_FOCUSABLE` 收不到 KEYCODE_BACK，取消按钮必须界面自带。
10. **框选起点别贴着屏幕左/右边缘划**：会被系统当成返回手势（操作时注意，代码无关）。

## 术语表怎么用（固定人名 / 专有名词的译法）

设置页 → 术语表，一行一条 `原文=译名`，支持多行（可以在别处写好清单，长按输入框粘贴进去）：

```
五条悟=五条悟
宿儺=宿傩
vault=仓库
```

**为什么需要它**：模型对同一个词会"飘"。实测 `vault` 在 v2 基线记的是「仓库」，
但连跑三次都稳定输出「库」（输出 token 完全一致，说明不是随机波动）。
`Shared vaults` 官方译法也是「共享仓库」而非「共享库」。

**日文人名尤其明显**：同一个人名可能被译成不同汉字或音译，出现"一个人两个名字"。
两类情况：
- 想固定成特定写法（含"保持原文不翻"）→ 在术语表里写 `ヒロ=希罗`、`五条悟=五条悟`
- 表里没列到的 → 加了约束让模型**同一名称前后译法一致**（这段约束只在术语表非空时追加，
  术语表留空时 Prompt 与实测规格**一字不差**）

**实测（2026-09-15，测试图 `tools/jp_test.png`）**：

| 用例 | 结果 |
|---|---|
| 不带术语表 | 模型自己把 `ヒロ` 稳定译成「希罗」、`エマ`→「艾玛」（6 句里各出现 3/2 次都一致）|
| `ヒロ=英雄;エマ=艾玛` | ✅ 输出 3 处**全部**是「英雄」——**手动指定压过了模型默认** |
| 全角 `ヒロ＝希罗`（日文输入法默认打出的 `＝`）| ✅ 一样认，不必特意切成半角 |

> ⚠️ 测"人名固定"时**不能随便写个译名**：这张图模型默认就译得对，
> 得故意指定一个它绝不会自选的（如 `ヒロ=英雄`）才证明得了。生成脚本见 `tools/make_jp_test.py`。

代价：术语表非空时输入 token 约 +54（那段人名一致性约束），耗时实测 1.30~1.45s，仍远低于 3s 要求。
